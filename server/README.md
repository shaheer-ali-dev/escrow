# BlockSub backend

The server builds unsigned native-SOL Anchor transactions. Wallets sign and submit them; the server never receives or stores private keys.

## Start

```bash
anchor build
cd server
cp .env.example .env
# Set MONGODB_URI, JWT_SECRET, BLOCKSUB_PROGRAM_ID
npm install
npm run dev
```

`BLOCKSUB_IDL_PATH` is resolved from the repository root. The default expects `target/idl/blocksub.json` generated by `anchor build`.

## Auth

- `POST /api/auth/signup`
- `POST /api/auth/login`
- `GET /api/auth/google`
- `GET /api/auth/google/callback`

## Profile and wallet

- `GET /api/profile`
- `PATCH /api/profile`
- `POST /api/profile/wallet/verify`

## Escrow transaction endpoints

All require `Authorization: Bearer <JWT>` and a verified client wallet profile:

- `POST /api/escrows/transactions/create` body `{ freelancer, totalLamports, milestoneCount, deadline }`
- `POST /api/escrows/:address/transactions/milestones` body `{ index, amountLamports, dueAt }`
- `POST /api/escrows/:address/transactions/release` body `{ freelancer, index }`
- `POST /api/escrows/:address/transactions/cancel`
- `POST /api/escrows/:address/sync` body `{ signature }`

Each transaction endpoint returns base64 unsigned transaction data plus PDA addresses. The frontend signs and submits the transaction, then calls sync with the confirmed signature.

The current on-chain MVP uses SOL lamports, client approval, and no dispute/timeout path. Use devnet until the contract is independently audited.
